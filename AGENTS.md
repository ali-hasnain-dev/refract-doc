# AGENTS.md

Compact guidance for working in this repo. The full Laravel Boost behavioral
rules (skills, Pint, Pest, Inertia v3 specifics) are managed by `laravel/boost`
and injected automatically — see `boost.json` / `opencode.json`. Only
repo-specific, non-obvious facts are listed here.

## What this repo is

A **documentation site** for the "Larafusion" Laravel admin-panel package
(Filament-inspired, React + Inertia). It is built on the Laravel + Inertia +
React starter kit.

- Doc pages are **Markdown files in `resources/docs/`**, mapped to URLs via
  `config/docs.php` (`nav`, `name`, `tagline`, `github`). Slugs there become
  `/docs/{slug}` routes (`routes/web.php`).
- Rendering is done by `App\Services\Docs\DocsNavigator` (nav + prev/next) and
  `DocsRenderer` (league/commonmark -> HTML, table of contents, `.md` links
  rewritten to `/docs/{slug}`).
- **Gotcha:** rendered HTML is cached forever per file, keyed by the source
  file's mtime. Editing `resources/docs/*.md` shows up only after the cache
  key changes; if a change looks stale, run `php artisan cache:clear`.
- To add a doc page: create the `.md` file in `resources/docs/` **and** add a
  matching entry to `config/docs.php` `nav` (the `file` is relative to
  `resources/docs`, `slug` is the public path).

## Environment & setup

- Local dev uses **Lerd** (`.lerd.yaml`): services are MySQL (`lerd-mysql`),
  Redis (`lerd-redis`), Mailpit (`lerd-mailpit`), plus a `vite` worker.
- `.env` is **Lerd-specific** (MySQL, `APP_URL=https://doc.test`) and is
  gitignored. `.env.example` uses sqlite and is what CI copies. Do not overwrite
  `.env` with `.env.example` locally — `php artisan dev` expects the Lerd hosts.
  `.env.before_lerd` is a backup of the pre-Lerd env.
- Full setup: `composer setup` (installs deps, builds assets, migrates).
  Run the app with `composer dev` (starts `php artisan dev`, which also boots
  the frontend dev server).

## Commands (verification)

PHP (Composer scripts in `composer.json`):
- `composer lint` — fix PHP style with Pint (`pint --parallel`).
- `composer lint:check` — Pint check only.
- `composer types:check` — PHPStan (level 7, `phpstan.neon`).
- `php artisan test` — full Pest suite.
- `php artisan test --compact --filter=testName` — single/ focused test.
- `composer test` — runs `config:clear` -> `lint:check` -> `types:check` ->
  `artisan test` (the canonical full check).

Frontend (npm scripts in `package.json`):
- `npm run lint` / `npm run lint:check` — ESLint.
- `npm run format` / `npm run format:check` — Prettier (only `resources/`).
- `npm run types:check` — `tsc --noEmit`.
- `npm run build` — client assets; `npm run build:ssr` — also builds SSR.
- `npm run dev` — Vite HMR dev server.

CI order (`.github/workflows`): tests job does `cp .env.example .env`,
`key:generate`, `npm run build`, `composer types:check`, then `artisan test`.
Lint job runs `composer lint`, `npm run format`, `npm run lint`. Run
`composer lint` + `npm run lint` before pushing so the linter job is green.

## Frontend / generated code

- `resources/js/actions`, `resources/js/routes`, and `resources/js/wayfinder`
  are **generated by Wayfinder** (gitignored). Do not edit them by hand — run
  `php artisan wayfinder:generate` after changing routes/controllers. Import
  route functions from `@/actions/` or `@/routes/`.
- Inertia v3: `Inertia::lazy()` is removed (use `Inertia::optional()`); Axios
  is removed; `DocsController` uses `Inertia::once()` for repeated props.
- Vite config uses the React Compiler (`babel-plugin-react-compiler`) and
  Tailwind v4 via `@tailwindcss/vite`. It ignores `vendor/`, `storage/`,
  `.git/` in watch to keep HMR startup fast.
- Docs syntax highlighting uses `shiki` on the frontend.

## Conventions that differ from defaults

- Tests use **Pest** (`php artisan make:test --pest {Name}`); most are feature
  tests. Do not delete tests without approval.
- PHP must pass Pint (`vendor/bin/pint --dirty --format agent` after edits) and
  PHPStan level 7.
- Use `php artisan make:` for new PHP classes; prefer named routes + `route()`.
- After editing PHP, run Pint; after editing frontend, run ESLint/Prettier.
